## Findings

Code not attached and therefore unverifiable by me: the runner (`run_eval`/`judge_runs` semantics, decoding settings behind `deterministic_judge`), METRON drivers, `config/panel.toml`, ADR-0008/0012 texts, dataset contents beyond the counts quoted in the spec, and the AXON generator model. I flag these inline rather than assume.

**1. BLOCKING — Rubric frozen before the owner has graded anything (labeling rubric section, JA-15).**
EvalGen's central result is that criteria cannot be fully fixed before looking at outputs; graders revise while grading, and the same natural-language criterion admits divergent implementations. "Supported by CONTEXTS" is exactly such a criterion for a notes vault: paraphrase granularity, derived values (23/34 answers contain digits — counts and date arithmetic are *derived*, not literally present), bridging inferences. Concrete failure: the contested cases (per-case judge deltas of 0.8–1.0, ~a third of N) will concentrate in exactly these ambiguities. Either the owner applies the rubric literally, derived-claim answers become "fail," and alignment.md concludes "rubric strictness, GLM-4.6 correct" — a tautology manufactured by the rubric, not a measurement — or the owner resolves ambiguity ad hoc mid-session, producing undocumented drift and labels inconsistent across the session, which no requirement detects. Smallest fix: grading-first two-pass protocol — owner grades 10–15 items including the contested ones, revises the rubric, freezes v2, then labels all 68 and re-labels the first pass; alignment.md records the rubric version and which cases changed. Cost: ~15 extra labels.

**2. BLOCKING — One declared threshold binarizes three differently calibrated judges; the report conflates calibration with discrimination, and the threshold is not pinned before labeling (JA-10, JA-15, "threshold sweep" deferral).**
Llama mean 0.749 vs GLM 0.382 on identical responses. At threshold 0.75, GLM passes a small fraction of items. TPR, TNR and kappa are all computed on the binarized verdict, so the entire report is a function of an operator-chosen constant that Task 5 never pins (and the gate's 0.75 is a `ci_low`-on-the-mean construct, not a per-case cut — the only threshold with a priori meaning from the judge's own scale is the anchor 1.0, per the prompt text). Concrete failure: a GLM whose *ranking* of cases perfectly matches the owner's can still post TPR ≈ 0.3 and kappa ≈ 0.13 at 0.75 (owner 80% pass, GLM 20% pass, GLM's passes a subset of the owner's: observed agreement 0.41, expected 0.32). alignment.md then reads "GLM misaligned" and the faithfulness_v2 decision rewrites a prompt to fix what is a calibration offset. Note the deliverable question — "judge error or rubric strictness" — is *itself* a threshold question. Smallest fix: pre-register the threshold in alignment.md before labeling begins (0.75 as the gate-mirroring primary), and report a second per-judge binarization at the owner-prevalence-matched quantile per arm; key "which judge matches the owner" to the matched statistic and "would the gate see it" to the fixed one. Rerunning is one command and ~400 judge calls; this is a procedural fix, not new surface.

**3. BLOCKING — The fail class is easy and the informative stratum is nearly empty (A8, A10, JA-14; Husain: 30–50 per label, below 60 the CI is too wide; Yan: 30–60% recall on inconsistent summaries).**
Fail labels come from the OFF arm (empty contexts — any factual claim fails, near-deterministic modulo abstentions), 61 blatant perturbations (digit absent from every context; one fixed appended sentence), plus the real ON failures, likely 5–10 items. Concrete failure: ON-arm TNR — the only coverage number that matters — gets Wilson intervals like 4/6 → [0.44, 0.98]; A10 concedes this yet Task 5 still expects a coverage-flavored verdict. Meanwhile the perturbations are lexical mismatches Yan's "blind spots" literature says judges catch easily, so every synthetic coverage number reads 0.9+ and the doc implies real failures would be caught — the opposite of the documented failure regime. Smallest fix within existing machinery: owner authors 15–20 hard negatives for his own vault (plausible paraphrased unsupported claims, human-authored in the Blind Spots style) as a `perturbation:owner` arm, fail by construction like A8; and pre-register "cannot decide" as a valid Task 5 outcome for ON-arm TNR.

**4. BLOCKING — Task 5's deliverable is an error-analysis conclusion, but no requirement performs error analysis (Task 5 acceptance vs Husain).**
"Judge error or rubric strictness" is per-case attribution; TPR/TNR/kappa cannot attribute a single verdict. JA-08 collects owner critiques (the right raw material) but nothing aggregates them. Concrete failure: whoever writes alignment.md either over-claims from aggregates or does an unrecorded ad hoc read; faithfulness_v2 then starts with no root-cause counts. Smallest fix: one acceptance criterion — a table of every owner-vs-judge disagreement with the owner's critique coded into ≤4 pre-named causes (derived claim / true-but-ungrounded / paraphrase-read-as-support / abstention handling), counts reported. Owner time only.

**5. ADVISORY — Single labeler, one pass, no reliability ceiling (JA-15; Yan: the baseline is human annotators, kappa between them).**
Blinding to judge scores is handled correctly (JA-14 exports no judge scores; scoring re-queries the judges). But judge-vs-owner kappa of, say, 0.45 is uninterpretable without the owner's own consistency: if owner self-kappa is ~0.5 the judges are at ceiling; if 0.9 there is real disagreement. Relative GLM-vs-Llama comparisons on shared labels survive label noise; absolute claims don't — and Task 5's attribution question is absolute. Smallest fix: owner re-labels ~20 randomly drawn real items blind after a delay; report owner self-agreement as the ceiling. ~30 minutes, and doubles as QC on the 68-item session.

**6. ADVISORY — B4's new floor is asymmetric and dormant (JA-05/06/07, A9; deferred driver and re-screening).**
The rule rejects over-crediting only. An always-fail judge — the GLM-adjacent failure mode this feature exists to adjudicate — passes the floor trivially, and the pass-class probes B4 already collects (expected_answer vs expected_contexts) are still never score-checked. Concrete failure: future candidate selection is biased toward strict judges, reopening exactly the "which extreme is wrong" question. Also: no in-repo caller of `screen_candidate` exists, so the floor changes nothing operationally until an out-of-repo script passes the new probes. Smallest fix: one clause in JA-05 — pass-class probes must score ≥ threshold; and either commit the trivial driver or state in `selection.md` that B4 is currently dormant.

**7. ADVISORY — The `overall` stratum contradicts A8 itself and EvalGen's "sample to the output distribution" (JA-10 vs A8).**
JA-10 mandates overall plus per arm; overall pools 61 construction-labeled blatant negatives and ~34 empty-context fails with 34 real ON items. Concrete failure: the quotable line becomes "overall TNR 0.96 [0.92, 0.98] for every judge," implying coverage the real stratum cannot support (finding 3). A8 names this exact hazard, then JA-10 computes it anyway. Smallest fix: overall over real arms only; perturbation arms reported separately.

**8. ADVISORY — Instrument noise at the cut point (JA-12, NFR-03; Yan: CoT helps).**
I cannot see the runner, so I cannot verify that `deterministic_judge` means temperature 0. If it doesn't, a per-item score near the threshold is a coin flip that binarization hard-codes into a verdict; with `judge_runs=1` there is no averaging (and note JA-12 thresholds the *mean* of runs, not a majority vote — different estimators). Freezing the v1 no-reasoning prompt during measurement is correct sequencing (NFR-01); but the align run can cheaply set `judge_runs ≥ 3` — JA-13 already declares the cost. Smallest fix: pin judge_runs = 3–5 in the Task 5 run config and state in alignment.md whether verdicts are single-draw.

**9. ADVISORY — Bias checks absent; generator family unrecorded (Yan: self-enhancement 10–25%).**
Nothing records which model AXON serves as the answer generator (I cannot see it). If it shares a family with a panel member — Llama and Mistral are plausible RAG generators — that judge's numbers carry self-preference. Smallest fix: record the generator model in alignment.md and flag any same-family judge in interpretation. Position bias is N/A (no pairwise); verbosity mostly N/A here.

**10. ADVISORY — Scoring-input integrity and underspecified export fields (JA-12, JA-14).**
`gnomon align` scores the `answer`/`contexts` copies inside the labels file with no tie to the run JSON; a hand-edit while filling verdicts silently changes what is scored versus what was labeled. JA-14 also never states that perturbation items carry the perturbed `expected_answer` against `expected_contexts` — inferable from JA-04, but it determines which distribution the probes test. Smallest fix: export writes a per-item checksum over answer+contexts that align verifies; one sentence in JA-14 pinning the perturbation item's fields.

## Deferral audit

- **Splits:** justified now — nothing iterates against these labels in v1, and N=68 cannot support splits anyway (which itself shows this is a pilot, not Husain's labeled corpus). Add one guard: declare the JA-15 labels test-only, or they silently become faithfulness_v2's dev set and are burned.
- **Threshold sweep:** fine for the tool, not for Task 5's decision (finding 2).
- **Re-screening pinned members / driver:** acceptable — alignment measures the panel as pinned, and JA-07's note is honest; but see finding 6 on dormancy.
- **CoT / prompt redesign / faithfulness_v2:** correctly deferred behind measurement.
- **Free-text entity swap:** lower priority than owner-authored hard negatives (finding 3).
- **Construction-labeled pass items rejected:** the right call — `expected_contexts` are anchors, and auto-passes would inject label noise into the one stratum that matters.
- **Omitted, not deferred, not justified:** error analysis (finding 4), bias checks (finding 9), label reliability (finding 5), and Husain's "code assertions where possible" — a digit-in-contexts regex would give a free second opinion on the 23 digit-bearing answers; optional.

**Over-built:** the `overall` stratum (finding 7); interleaving perturbation items into the owner's labeling file (a separate file keeps construction labels out of the owner's path); ADR-note plus selection.md plumbing for a floor nothing currently executes; JA-13's pre-call cost print is harmless.

## Final paragraph

No — I would not run Task 5 as specified. As written it will produce a threshold artifact (finding 2) evaluated against a rubric tautology or undocumented drift (finding 1), dressed in intervals that cannot support the coverage half of its verdict (finding 3) and with no mechanism to produce the attribution its acceptance demands (finding 4). The minimum change that makes the result decision-useful is small and mostly procedural: run labeling grading-first with the rubric frozen at the *end* (re-labeling the first-pass items and recording the version), pin the threshold before labeling, and report both the fixed 0.75 and per-judge prevalence-matched binarizations, with the "judge error vs strictness" verdict keyed to the matched statistic. That yields a defensible answer to the false-failure question (GLM's ON-arm TPR plus per-case attribution) and an honest bound on coverage. The hard negatives, disagreement table, and owner re-label pass (findings 3–5) raise how much the numbers can say, but those two changes are what make the output an answer rather than an artifact.
